# Deferred CEF C API loading

This local `cef-dll-sys` patch keeps the ABI of `154.5.0+154.0.34` while removing CEF from the executable's startup imports. A missing runtime must leave the native source editor available. The upstream Windows/Linux build links CEF before application preflight can run.

The four files in `bindings/` are byte-for-byte upstream generated bindings from [cef-rs commit 2861f6991fae3ee31f877891382adcbc9b9f0953](https://github.com/tauri-apps/cef-rs/tree/2861f6991fae3ee31f877891382adcbc9b9f0953/sys/src/bindings), distributed as `cef-dll-sys 154.5.0+154.0.34` (crate checksum `a52b7101d21b13aaa09e5047510bc6b6720140de0ee2a65d132b9fd70fbf5f69`). `upstream.json` records their SHA256 hashes. The original Apache 2.0 and MIT licenses are included and packaged with the application.

`build.rs` parses each target's generated declarations with `syn`. It preserves all types, constants and layout assertions, replacing C imports with typed wrappers and one complete symbol table. Unsupported foreign declarations fail the build. Loading resolves every symbol before publishing the table, so a missing dependency or symbol returns an error without exposing a partial API. The application validates required resources before calling `load_library`, then selects the pinned API version before constructing CEF values. Its desktop subprocess follows the same order.

The library handle stays alive for the process lifetime because CEF callbacks and reference-counted objects can outlive individual views. Calling an entrypoint before loading is an internal safety violation and prints a diagnostic before aborting; it never returns fabricated C values. Headless GPUI initialization rejects CEF before any load. The native sandbox feature fails explicitly: this application uses the existing verified production confinement boundary, with sandbox disabled. Supported targets are Windows and Linux, x86_64 and aarch64.

Runtime provisioning retains the pinned upstream `download-cef 3.0.0` archive verification, `CEF_PATH` layout, automatic download when absent, Nix/Flatpak inputs, and flat Cargo-profile staging. It performs no native wrapper build or CEF link directive. Fresh SDK staging is verified separately from warm application builds. Application packaging still validates the minimal archive identity and complete runtime/resource closure. Linux packages discover dependencies of both the application and the dynamically loaded CEF library.

Run the ordinary loader test with `cargo test --locked -p cef-dll-sys --lib`. For native integration, set `LATHE_TEST_CEF_LIBRARY` to the pinned runtime library and `LATHE_TEST_OTHER_LIBRARY` to a trusted native fixture without CEF symbols, then add `-- --include-ignored`. Installed application acceptance also physically withholds its own CEF library/resources and requires Open Source to activate the same Buffer.
