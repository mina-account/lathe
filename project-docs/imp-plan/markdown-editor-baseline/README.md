# Markdown editor Phase 0 baseline

Observed 2026-10-12, against Marketplace `zaaack.markdown-editor` **0.1.21** and source commit `033c6242cf96615fd0c88bed73d5428b76e3a44b`. This freezes the reference and the future acceptance corpus. It adds no Lathe editor implementation. Every Lathe acceptance row remains pending.

## Evidence and reproduction

`fixtures.json` contains the P01–P22 acceptance procedures, source preservation inputs, HTML paste, settings, keyboard controls, path cases, and valid/invalid renderer inputs. `evidence.json` records actual browser outputs, serialized Markdown/HTML, toolbar/options, source comparisons, renderer DOM/error observations, and attempted resource requests. `runtime.json` freezes runtime entrypoints by SHA-256 and theme choices.

The extension was installed with VS Code 1.95.3 (`f1a4fb101478ce6ec82fe9627c43efbf9e98c813`, x64) into an isolated temporary extension directory and profile using `code --install-extension zaaack.markdown-editor --extensions-dir <extensions> --user-data-dir <profile>`. Its installed package was tested, rather than substituting an npm Vditor demo. Source dependencies were installed with **pnpm 10.28.2**, `--frozen-lockfile --ignore-scripts`. The source frontend was built with its locked **esbuild 0.28.1**; the host was built with its locked **TypeScript 4.2.2**. The harness uses **Node 24.16.0**, locked **Playwright 1.56.1**, and Edge **155.0.4283.45** on Windows.

Reproduce outside the repository for downloaded reference code and dependencies:

```powershell
git clone https://github.com/zaaack/vscode-markdown-editor.git <reference-source>
git -C <reference-source> checkout 033c6242cf96615fd0c88bed73d5428b76e3a44b
# In <reference-source>:

node node_modules/esbuild/bin/esbuild media-src/src/main.ts --bundle --minify --sourcemap --outfile=media/dist/main.js
node node_modules/typescript/bin/tsc -p .
# In this baseline directory:
npm.cmd ci --ignore-scripts
node probe.mjs <installed-extension-directory> <reference-source> <Chromium-executable> actual.json
node verify.mjs
```

The probe runs the installed and rebuilt frontend bundles in a real browser, supplies a recording `acquireVsCodeApi` stub, and intercepts their Vditor 3.11.2 CDN requests with the exact locked npm distribution. Other external requests are recorded and blocked. This permits deterministic local runtime tests; it does **not** prove the Marketplace extension runs offline, VS Code host integration, native IME, or GPUI hosting. Renderer observations are taken after a bounded 1.8-second wait, with failures and pending/service output retained as evidence. No downloaded upstream code is redistributed here.

## Published/source comparison

All seven extension frontend source files recovered from the installed source map match the pinned source after CRLF normalization, including `search.ts` and `fix-table-ir.ts`. Recompiled `out/extension.js` also matches the published host after CRLF normalization. The bundle hash is recorded in `evidence.json`. Both the installed map and lockfile resolve Vditor **3.11.2**, rather than inferring the dependency from its `^3.8.4` range.

Therefore **P21 Find and P22 table wrapping are present in the published 0.1.21**. They are required published parity, despite the original plan describing them as source additions. The baseline options enable `footnotes`, GFM autolinks, code block preview, math block preview, sanitized HTML, and media rendering. `toc` defaults to **false**; `[toc]` remains literal unless explicitly enabled through stored options. KaTeX is selected with `inlineDigit: true`. MathJax exists in the distribution but no exposed toolbar/manifest setting selects it, so it is not required parity. Heading `{#id}` is parsed differently across modes and must remain preserved as source.

The custom toolbar excludes Vditor's microphone `record`, export/PDF, and speech controls. It includes preview's mobile/desktop/tablet and clipboard adaptation for WeChat/Zhihu; these copy locally and do not publish to a third-party service. Existing `<audio>`/`<video>` content may render; creation/recording/publishing remain outside scope.

## Finite renderer scope

Required fence handlers are **mermaid, graphviz, echarts, abc, flowchart, plantuml, markmap, smiles, math**, plus the runtime's **mindmap** handler. Mindmap expects `data-code` carrying URL-encoded JSON generated by Lute's Markdown mindmap form; an ordinary `mindmap` fence is also included to expose that distinction. WaveDrom and standalone `sequence` fences are negative controls: no renderer adapter selects those languages. Mermaid's sequence diagram syntax is supported inside a `mermaid` fence. Each handler has valid/invalid fixtures and recorded DOM results; a renderer error is reference evidence, not permission to omit the feature from Lathe.

The default CDN is `https://unpkg.com/vditor@3.11.2`. Runtime requests include Lute, icons, language packs, code highlighting/themes, KaTeX plus mhchem/fonts, and the fence-specific scripts listed in `runtime.json` and `evidence.json`. Graphviz constructs a blob worker which imports `full.render.js`. PlantUML loads the local encoder but renders an object from `https://www.plantuml.com/plantuml/svg/~1...`; it is a **service-backed renderer**. Lathe must either make that service explicit or bundle a reviewed alternative. Markmap can also request its own CSS dependencies; package all observed local dependencies.

ECharts uses upstream `looseJsonParse`, implemented with `Function(...)`; Lathe must use validated data-only JSON instead. Matching executable chart payloads is deliberately prohibited by the implementation plan. Source rendering must not grant document HTML or SVG access to host bridge permissions.

Cold-page tests render all local handlers. PlantUML generates its service object, whose network request is deliberately blocked. Malformed Graphviz/ECharts/math produce visible error text; malformed flowchart throws an uncaught page error. ABC, Markmap, mindmap and SMILES accept or tolerate the generic malformed payload; that does not establish valid semantic output. Mermaid renders its error SVG rather than using `.vditor-reset--error`. SVG counts can include code-copy icons and must be interpreted with the recorded HTML, text, and `data-processed` fields; the negative controls remain ordinary highlighted code. A separate exploratory sequential run found ABC/SMILES collide on `vditorAbcjsScript`, producing `SmiDrawer is not defined` after ABC has loaded. Later phases must give renderer scripts distinct identities.

Observed global versions are ECharts **5.5.1**, ABC **5.10.3**, and math KaTeX **0.16.9**. Markmap bundles another KaTeX **0.16.0** into its script. Pin the distribution bytes rather than replacing transitive renderers with current releases.

## Measured preservation risks

The exact input and output strings are committed in `evidence.json`, for every mode and both baselines. These are initial `getValue()` round trips, before any user edit:

| Input | Measured consequence |
| --- | --- |
| Reference definition with title | Title disappears in all three modes. |
| YAML front matter | IR/WYSIWYG remove the blank line after front matter; split adds a trailing blank line. |
| Raw HTML entity | IR/WYSIWYG decode `&amp;` to `&`; split retains entity but adds a trailing blank line. |
| Inline/block math | Preserved in IR/WYSIWYG fixture; split adds a trailing blank line. |
| Unknown fence `unknown-engine extra` | Info suffix disappears in all modes; split also strips leading content indentation. |
| Unicode/emoji/combining characters | Characters preserved; split adds a trailing blank line. |
| CRLF | All modes normalize to LF. |
| Missing final newline | IR/WYSIWYG add one newline; split adds two. |
| CommonMark/GFM | List spacing/check case, autolinks, and table alignment normalize. |
| Heading explicit ID | WYSIWYG removes `{#explicit-id}`; TOC is not automatically enabled. |

HTML paste with a paragraph, bold text, and a link produces Markdown emphasis and a Markdown link. Ctrl+F opens Find and reports `1/3` for `find` against `Find find FIND`; Find and table wrapping are checked against the serialized source. Mode switches add whitespace and normalize table alignment; their output is recorded separately. These controls must not make latent serialization changes authoritative.

The reference stores mode, editor theme and `preview` options in synced `globalState`; its scroll map is in-memory. Its serializer does not retain outline or table-wrap state. Full document-scoped persistence, outline/wrap retention, host history and read-only permission rejection in the plan are explicit Lathe requirements beyond this reference behavior.

**Adapter requirement:** never send the initial serialized value or a no-op mode/theme/find change to the buffer as an edit. A whole-document diff against Vditor output still loses untouched titles/entities/fence suffixes. Phases 2–3 must preserve source spans with block/source mapping, retain original newline policy, and expose unsupported blocks as editable source. Host-owned undo and IME require separate integration tests; `clearStack` exists but is not proof that Vditor's local undo has been safely reconciled.

## Phase 0 verification and later gates

The browser probe compares published and pinned round trips and asserts actual Find/table-wrap presence, source preservation through table toggle, initialization without page errors, Vditor version, and complete P01–P22 fixture coverage. `verify.mjs` validates committed fixture/evidence/runtime consistency without external dependencies or downloads. `git diff --check` is required before commit.

Application Rust checks are intentionally not run for this documentation/fixture/harness-only phase. TDD's expected-red application test requirement does not apply to collecting baseline behavior; inspecting the first evidence output exposed an encoding-corrupted Unicode fixture, which was corrected and then guarded by an assertion. No new Rust component exists yet. This is not evidence of Lathe parity, packaged offline operation, native host integration, or cross-platform success. Phase 1's Windows/macOS/Linux X11/Wayland composition and IME gate remains mandatory before editor implementation proceeds.
