# Mini implementation plan: Reduce AI chat cold-start work

Status: Implemented and verified on Windows; ready for independent PR review.
Base branch: `main`.
Validation platform: Windows.

## Problem and scope

New and restored conversations both wait for `AgentConnectionStore` before creating or loading a session. Connections are reused within the project, but the first npm-backed agent connection runs `npm install` unconditionally in `LocalRegistryNpxAgent::get_command`. `SystemNodeRuntime::new` also deletes its npm cache. Local Codex logs confirm repeated installation checks and registry requests during startup. Remove this repeated work without changing chat/session persistence, authentication, agent selection, archive/custom-agent launch, or environment precedence. Agent process startup and its handshake still remain; do not promise a measured end-to-end speedup without measuring one.

## Implementation

1. Preserve the system Node runtime's npm cache across runtime initialization and application restarts. Create missing directories idempotently and propagate initialization errors. Use an isolated directory seam for tests so they never modify the user's real cache.
2. Add a persistent validated-install fast path for npm registry agents in the existing agent-server implementation. For an unchanged pinned numeric package specification and a usable installed package/executable, return the launch command without running npm or accessing the network. Support scoped packages and existing installations. Verify the installed package version and that the executable is a regular file; do not trust only the directory's existence.
3. Keep first installation, requested package/version changes, missing/corrupt package metadata, and missing executables on the install/repair path. Preserve `bounded_npm_package_spec` and the user's minimum-release-age policy: an older version successfully selected by npm may be reused for that same registry specification using a successful-install receipt. Publish any receipt only after installation and executable validation succeed. An interrupted/failed install must not establish a valid receipt. Permission and other I/O failures must remain visible rather than becoming silent cache hits.
4. Preserve update behavior: a changed registry package specification invalidates its previous receipt. Mutable/unpinned specifications (tags/ranges) must retain their existing resolution behavior rather than becoming permanently frozen. Do not add background live-package mutation while an agent is running. Coordinate concurrent install/repair requests for the same installation directory so one operation cannot validate or launch another operation's partial installation.
5. Keep command arguments, proxy handling, project environment, Node PATH injection, distribution/settings environment precedence, and error propagation to the existing connection/chat error UI intact. Avoid changing the shared new-session/load-session gating; both benefit from the same launcher fix.

## Verification and acceptance

- Use focused regression tests first where practical and record the expected failing result before the fix. Exercise the actual install/launch decision with a counted fake npm runner or an equivalent deterministic seam, not only a standalone predicate.
- Cover two fresh launcher instances sharing an installation (restart equivalent): a valid unchanged pinned install performs zero npm calls; cold install performs one and subsequent open performs none; requested-spec changes and missing/corrupt metadata/executables trigger installation; failed install remains retryable; bounded older-version reuse works; mutable specs still resolve; scoped packages and paths with spaces work; concurrent requests do not race installation. Verify preserved arguments/environment through the relevant launcher test.
- Verify a sentinel in an isolated npm cache survives repeated initialization and directory creation errors propagate.
- Run Windows `cargo test -p node_runtime --lib`, focused project agent-server tests (`cargo test -p project --lib --features test-support agent_server_store::` to include the install helper's tests), affected-file Rust formatting, the repository `script/clippy.ps1` wrapper scoped to affected packages, and `git diff --check`. Discover required Windows compiler/build environment from the existing scripts. No Linux validation is required for this increment.
- If full project test linking or package Clippy has a reproducible unrelated baseline blocker, demonstrate it against the unchanged base, run the strongest focused production-code tests/checks available, and record the precise limitation. A failing task regression is never an acceptable exception.
- Keep the scope limited to these fixes and this plan. Commit the plan with implementation and update its status/evidence before review. No installer/release publication or installed-application replacement is included.

## Delivery

Use `imp-wt-loop-1`: a new worktree based on fetched `origin/main`, implementation subagent, PR, fresh read-only `$review-agent` review plus plan-completeness review, fixes and re-review until clean (maximum five review passes), then squash merge the exact reviewed head and normal worktree cleanup. Preserve unrelated primary-checkout edits; update the primary checkout only when clean and a fast-forward is possible.

## Implementation and verification evidence

- System-runtime cache initialization now creates the cache idempotently and propagates directory errors. A temporary-directory sentinel test failed with the original cache deletion and passes with cache preservation. The complete Windows `node_runtime` library suite passes: 23 tests.
- Registry-agent launches validate the installed package version and executable under an OS file lock. Existing exact pinned installations are accepted without npm. A receipt records the requested specification and the version npm selected, allowing a successful older bounded selection to survive restarts. Missing, corrupt, or mismatched state forces repair. The receipt is invalidated before npm starts and written only after validation; mutable tags/ranges continue resolving on each launch.
- In-flight installation retains its lock even if its requesting chat is canceled. The caller awaits a detached installation worker's result; if the caller disappears, installation errors are logged. This finishes the existing install operation and does not schedule periodic updates or mutate an active agent to check for updates.
- Counted fake npm closures exercise the production install decision. Three original-behavior regressions were observed first: existing installations ran npm twice instead of zero times, cold installation plus restart ran twice instead of once, and four simultaneous launches ran four installations instead of one. The cancellation regression separately failed before the worker retained ownership. A temporary extracted-helper harness enabled early red/green iteration; final verification compiles and executes the actual project crate, including all 12 new helper tests.
- Coverage includes scoped packages and paths with spaces; cold, existing, and older bounded installations; specification/package changes; missing/corrupt metadata and executables; failed installs and receipt publication; surfaced I/O errors; concurrent/canceled requests; argument order; and environment precedence (project, Node PATH, distribution, extra, settings).
- Final checks pass: `cargo test --locked -p node_runtime --lib` (23 tests); `cargo test --locked -p project --lib --features test-support agent_server_store::` (26 tests); `script/clippy.ps1 -p project -p node_runtime` (all targets/features, warnings denied); changed-file `rustfmt --check`; and `git diff --check`. Clippy uses `CARGO_PROFILE_RELEASE_OPT_LEVEL=0` and `CARGO_PROFILE_RELEASE_LTO=false` to avoid unnecessary release optimization during analysis. Visual Studio 2022 Build Tools and its CMake directory supply the Windows compiler environment.
- The unchanged base independently passes its 14 existing agent-server tests. Both base and changed project test linking emit the same pre-existing Wasmtime/tree-sitter LNK4217 warning. No baseline test or Clippy exception was needed. The full build caught and resolved a map-hasher mismatch in Node environment integration, and repository Clippy caught and resolved a redundant clone in a new test; no task failures remain.
- No end-to-end startup timing or installed-application replacement is claimed. New/restored session gating, authentication, and agent selection are unchanged.
