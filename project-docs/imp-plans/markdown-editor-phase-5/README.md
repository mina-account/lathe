## Opening and actions

The project-path opener applies only to `.md` and `.markdown`, case insensitively. It resolves the actual filename through `Project::absolute_path`, including standalone file worktrees whose relative path is empty. Clicked menu targets retain that real relative path and carry the filename separately for eligibility. It opens a visual Item over `Project::open_buffer` and keeps the ordinary Buffer-to-Editor builder intact. Explicit palette/menu invocation wins; workspace deserialization restores its recorded Item kind and preferences; otherwise an explicitly configured `markdown_editor.default_open_mode` wins over the legacy native-preview setting, which wins over source. The schema/default value is null so an untouched setting does not hide existing legacy preview preferences. The native preview observer consults this same path-specific policy and excludes restoration; explicit source opening uses its existing one-shot suppression mechanism.

Project-panel actions retain the clicked worktree/path, and tab actions retain the clicked Item identity. They offer Text Editor, Markdown Preview, Markdown Editor, and corresponding default setters. Palette actions use `Workspace::item_for_action`, and normal pane ownership/focus and error notifications. Open/Open To The Side/Open Source/Show Preview share the Buffer and reuse matching visual Items within the destination pane. Live visual Items flush before changing views. A stopped visual Item can open its original shared source Editor while retaining the Item and any recovery draft; save/close and other presentation switches retain their strict barriers. Copy Markdown/Copy HTML/Insert Image/Toggle Outline/Reset Preferences route to the focused visual Item's existing trusted controls; Set Mode uses the typed mode setting. Native preview actions remain independent.

The Windows/Linux default keymaps contain Ctrl-Shift-Alt-M in Markdown source and MarkdownEditor contexts. It survives the application's keymap clear/reload and does not bind unrelated source or terminals. Existing Ctrl-Shift-V and Ctrl-K V native preview bindings remain unchanged.

## Settings and restoration

The Settings UI exposes default opening mode, initial editing mode, image folder, content/code themes, application colors, line numbers, initial outline, custom CSS, and PlantUML service. Defaults are typed and registered in the existing settings schema. Per-document saved mode/themes/outline/wrap/reading position override subsequently changed initial settings. Existing workspace serialization/deserialization retains the same cached Buffer, file path, and unsaved recovery content, even after defaults change to source and another editing mode.

## Build and installed runtime

Windows/Linux build scripts run the locked frontend closure with Node 24.16.0 and compile `zed/markdown-browser` with `--locked`. Release CI and the existing Linux main-push/manual CI caller provision that build-only Node version before building on both Linux architectures. The updater helper, signing hooks, ConPTY/AGS, Inno packaging, release metadata, and updater workflows are preserved. Linux supports explicitly skipping system provisioning in an already prepared contributor environment.

Oversized/high-DPI viewports retain their logical geometry and use a bounded raster scale to stay within the existing 16 MiB frame budget. Ordinary scales are preserved. The package stages CEF 154.0.34 / Chromium 154.0.8037.98 from the bindings' pinned minimal archive beside the installed GUI executable, including all locales and required graphics/resource files. It records file hashes in `markdown-runtime.json` and `markdown-runtime.sha256`, ships CEF credits/license and frontend dependency notices, and uses the installed GUI executable as the CEF subprocess helper. Linux uses an executable-relative runtime/library search path. CEF loads dynamically only after complete resource validation, including in the desktop subprocess. Missing libraries/resources or unresolved native symbols produce a reinstall message and preserve source access; installers validate the complete staged runtime before replacing an existing installation.

The installation check is inert unless a host process explicitly sets `LATHE_MARKDOWN_INSTALLATION_CHECK` and opens the exact fixed `installed-fixture.md`. It is disabled under the GPUI test executor. Document content cannot enable it. It starts the normal installed application and production browser integration, checks exact Buffer/source preservation and real DOM output in IR/WYSIWYG/split/viewer, and exits through normal application shutdown. The report requires Vditor 3.11.2, KaTeX 0.16.9, local code styling, every finite bundled renderer, semantic Markmap/Mindmap labels, and PlantUML's explicit no-service error. It consumes only the existing validated Copy bridge message for its explicitly enabled Item.

Installed jobs use isolated user-data/install directories, disable updates and language servers, remove Node from PATH and unset SDK/runtime overrides for normal runs. HTTP/HTTPS/ALL proxies point to unreachable `127.0.0.1:9`; this demonstrates that local Markdown functionality does not require a successful network request, not a machine-wide firewall policy. The configured PlantUML service remains an explicit network feature and is not called or claimed offline. Actual installed executable, archive, runtime file hashes, CEF subprocess executable paths, and X11/Wayland environment provenance are retained in the acceptance artifacts. Shell integration is disabled for these isolated installs.
