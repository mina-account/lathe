# Phase 3 source-preserving rich Markdown Item

The existing shared native Buffer now drives offline Vditor **3.11.2**, with instant rendering as the default, WYSIWYG, split editing, and a read-only viewer presentation. This is the actual Vditor DOM and serializer, including its formatting and table UI. The native source Editor still owns file operations and history. The native preview remains independent.

The implemented controls cover headings, bold, italic, strike, emoji, links, unordered/ordered/task lists, indent/outdent, quotes, rules, fenced/inline code, tables, insertion before/after, and native Undo/Redo. Copy Markdown emits the exact preserved source; Copy HTML emits sanitized serialized HTML as clipboard text. Selected copy and sanitized HTML/plain-text paste are supported. Outline navigation, heading/footnote/backlink/HTML-ID internal anchors, project-relative and external links, Find with count/previous/next/case/Escape, table wrapping, preference reset, and persisted mode/outline/wrapping/reading position are implemented. Relative links resolve from the owning project's absolute file path and open through the workspace; heading fragments support ATX, explicit IDs, and setext headings, with inline links, code, images, entities and HTML reduced to rendered heading text. Find refreshes its ranges/count/highlights after host projections, source-control changes, and rich/split commits. File-backed preferences are also stored by project document identity (owning absolute path and remote identity), and normal save/close preparation awaits that write before a clean tab can close, so Open restores them even on immediate close/reopen; item-keyed state remains available for workspace/untitled restoration. Footnotes are enabled and `[toc]` stays literal under the pinned reference's default `toc=false` behavior.

## Source and native ownership

Opening or switching a mode records Vditor's initial normalized serialization as a projection baseline. It never submits that serialization as an edit. `SourceProjection` maps canonical offsets back to the original UTF-16 source spans, including CRLF. Actual input and toolbar actions capture the intended block and unchanged neighboring blocks. Outstanding DOM input is captured before native flushes, host projections, mode rebuilds, and the next keyboard/mouse scope; boundary Backspace/Delete scopes include the affected neighboring paragraph. Rich edits serialize only the affected DOM block range, locate its unchanged neighbors (including repeated identical neighbors), and project the intentional changes back onto the untouched source. The canonical mapping retains its original block order across consecutive edits: Vditor reparsing can relocate references and footnotes, so subsequent whole-document serializer output cannot replace that mapping. Table cell edits retain unchanged row/cell padding and alignment syntax. Split edits are scoped to the selected source lines; split code/table/rule insertion uses bounded valid Markdown so upstream insertion cannot consume the following paragraph.

Frontmatter, raw HTML, explicit heading-ID blocks, fences, and reference/footnote definitions also have individually editable source controls. These controls edit their original spans and preserve CRLF. They do not replace the document's ordinary rich editing surface. Composition in either a rich surface or a source control holds incoming projections and save/mode barriers, then finishes and rebases independent host changes before releasing those barriers. Source updates and mode switches restore the selection and reading position. Native CEF input-state messages report the DOM's UTF-16 selection instead of treating rendered offsets as Markdown source offsets.

Every accepted nonempty source change remains a minimal native Buffer transaction. Native Undo/Redo is authoritative. Toolbar history commands queue behind edits and each preceding history acknowledgment; every command gets the updated native revision, including no-op acknowledgments. Concurrent independent source edits, canceled composition, save/close flush, autosave, multibuffer/cross-window saves, and retained crash drafts keep the Phase 2 controller guarantees. A recovered blocked draft can be copied without overwriting the native Buffer. Failed source mapping retains the visible DOM and emits recovery text with submission blocked; normalized serialization is recovery-only and cannot replace the authoritative original source.

## Rich content confinement

This phase revisits the Phase 2 plaintext boundary before rich content reaches live DOM. A pinned DOMPurify **3.4.17** sanitizes Lute-generated editing/preview HTML and clipboard HTML, including transformations during typing. Scripts, event attributes, SVG, embedded content, forms, media, document styles, and non-task inputs are removed. Only checkbox inputs needed by task lists survive; viewer and serialized output disable them while retaining checked/unchecked state. Dangerous link schemes are rejected again by the typed native bridge; external links use the host opener and relative paths use project/workspace APIs. Optional JavaScript renderer languages are displayed as inert code until Phase 4.

The packaged-resource allowlist is exact. CSP allows only packaged same-origin scripts, prohibits eval and inline scripts, and denies connect/image/font/worker/frame/object/base/form capabilities. Inline style support is limited to the trusted editor's layout needs; document styles are stripped. Trusted icons and Lute are loaded from packaged scripts rather than Vditor's synchronous script injection. Application controls are cached before mounting document HTML, so document IDs can remain available for anchors without redirecting trusted control access. Navigation, popups, downloads, permissions, foreign resources, and filesystem URLs remain denied. Typed messages validate size, shape, session, document, request/revision, Unicode offsets, URL schemes, and writable/viewer permissions before host actions. The viewer rejects forged native mutation/history messages too.

CEF remains pinned to bindings **154.5.0** and runtime **154.0.34**. The inherited `no_sandbox = 1` configuration has not become an operating-system sandbox. These are application/data confinement controls over a trusted packaged runtime. Phase 4 must retain this boundary when expanding assets/renderers.
